# 261118 开发日志

## 新建便签叠上负坐标便签修复（装箱避让哨兵混用，Go 逻辑层）

> 创建于 2026-11-18 13:01

**需求**：开发者实测：给便签开启「独立（于全局）样式」（样式锁）后新建便签，新便签无视该便签直接叠上；要求「相邻且不重叠」对所有便签生效，与是否独立样式无关。

**根因**（读用户实际 notes.json + 数据代入装箱模拟定位）：`packPos` 的「已摆放」判定用 `>=0`，把哨兵 -1（未摆放）与合法负坐标摆放混为一谈。用户便签实际落在 x=-6, y=0（拖到屏幕左缘/贴顶产生的非哨兵负坐标），`n.px >= 0` 与 `n.rec.X >= 0` 双双为假 → 该便签被 `continue` 排除出装箱避让 → `PackTopLeft` 收到空矩形表 → 新便签固定落 (8,8)，恰好在其覆盖区域 [-6,490)×[0,618) 内部，完全重叠。样式锁本身与几何无关（`rec.Style` 只影响 EffectiveStyle），负坐标对任何便签都触发，与「独立」只是表象相关。

**实施**：① `packPos` 判定改哨兵精确比较（`n.px != model.SentinelCoord`，回退分支同理），注释写明负坐标合法；② `ImportRecords` 装箱判定 `rec.X < 0 || rec.Y < 0` 同类混用一并改为哨兵精确比较（负坐标导入原位恢复，不再重新装箱丢弃位置）。`Start`/`StartHidden` 原本就用哨兵精确比较，未动；`PackTopLeft` 本身对负坐标矩形正确（带过滤与右推均覆盖），未动。

**验证**：TDD——先写两测试并确认按预期失败（`px=8 want=490` 复现叠上；导入被重新装箱），修复后转绿；`go build/vet/test` 全过。实机手测待开发者：负坐标便签在场时 alt+shift+c 新建应紧贴其右缘（当前数据下落 (490,8)），重启后位置不丢。

**涉及文件**：`internal/wm/controller.go`、`internal/wm/controller_test.go`（新增 TestPackAvoidsNotePlacedAtNegativeCoords / TestImportRecordsKeepsNegativeCoords）、`docs/log/261118.md`

## 销毁确认首次 y/n 无响应修复（三层焦点恢复，Go+前端）

> 创建于 2026-11-18 13:06

**需求**：开发者实测：alt+z 弹出「真的要删除吗」后第一次按/点 y/n 无效，需要第二次才生效；期望一次生效。首版修复（浮层 tabindex + rAF focus + Go 侧 win.Focus）后，连续第二轮销毁仍复现首按无效。

**根因**（对照参考实现 bugzia `NoteWindow.tsx` + Wails v3 源码 + 注入按键取证定位）：进入确认态时三层焦点均未恢复，首次按键撞上焦点过渡被吞——① 编辑框因 `ta.hidden=true` 被隐藏，DOM 焦点掉到 body，WebView2/IME 焦点态悬空；② 移植时丢了 bugzia 的 `tabIndex={-1}` + rAF 后 focus，`confirmEl.focus()` 对无 tabindex 的 div 是静默 no-op；③ `RequestDestroy` 注释写「显示+聚焦」实际只有 `Show()`（Wails `Show()` 仅 `SW_SHOW` 不抢前台，`Focus()` 才是 `SetForegroundWindow`+MoveFocus；框架在 WM_ACTIVATE 有 `restoreWebviewFocus` 但走 focusHandoff 门控）。中文 IME 下首按还可能以 `key:"Process"`（TSF 拦截）到达，`e.key` 匹配直接漏掉。鼠标路径同理：click 事件会在 mousedown→mouseup 间被焦点/DOM 切换吞掉，激活期首击也可能丢失——bugzia 用 pointerdown 捕获规避。

**实施**：① `frontend/note.html` 浮层 div 加 `tabindex="-1"`，Y/N 按钮加 `data-note-confirm`；② `frontend/assets/note.js`：`requestDestroy` 改 rAF 后 `focusConfirmOverlay()`（`confirmEl.focus()`，`document.hasFocus()` 为假时挂一次性 window focus 事件补焦）；键盘匹配改 `e.code`（KeyY/KeyN 物理键位，不受 IME 影响）兼容 `e.key`；Y/N 按钮从 click 改 pointerdown 捕获 + preventDefault（阻止焦点转移，不依赖 click 时序）；③ `main.go` `RequestDestroyConfirm` 先 `win.Focus()` 再 EmitEvent。

**验证**：`go build/vet/test` 全过。取证环境（SendKeys 键盘两连删 + EnumWindows 定位窗口真实鼠标点击 Y 按钮）均一次生效；临时诊断（keydebug 回传 e.key/e.code/hasFocus）已验证后移除。最终以开发者实机手测为准——开发者测试通过（2026-11-18）。注意：前端资源构建期内嵌，改动需重新 `go build` 才进 exe。测试期间自动化复现曾误删开发者一张空白测试便签（当时已知会）。

**涉及文件**：`frontend/note.html`、`frontend/assets/note.js`、`main.go`、`docs/log/261118.md`
