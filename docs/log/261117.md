## 阅读态/编辑态切换显示跳动（bug 修复 + 同引擎回归验证）

> 创建于 2026-11-17 12:13

**需求**：点击进编辑态与退出回阅读态时，便签文本显示位置必须固定，不得跳动滑动（开发者提出；上节点击定位已验证生效）。

**根因（Edge 同引擎 harness 逐步埋点定位）**：三个独立来源叠加。① `startEdit` swap 瞬间 ta 尚未撑开（只有 `min-height:100%`≈一屏），body 可滚动内容瞬时缩水，scrollTop 被钳制丢失（钳制不可逆，实测 400→4，4 = 瞬时 scrollHeight 690 − clientH 686）；`focusEditorAt` 里第二次 `syncTextareaHeight` 的 `height="auto"` 测量期会再次坍缩。② `ta.focus()` 默认把「当前光标」（文末）滚入视口，视图猛滚到底（实测 400→602 = max）。③ textarea 的 UA 默认 `padding:2px` 与 inline 布局基线空隙使两态内容高度差 4px、换行宽度差 4px，退出态在底部时 scrollTop 回移 8px。

**修复**（`frontend/assets/note.js` + `frontend/assets/note.css`）：`syncTextareaHeight` 内部先记后还 scrollTop（护住所有 auto 测量期坍缩，含打字路径）；`startEdit` 在 swap 前捕获、sync 后恢复（sync 内部防护救不了 swap 一步，两层都要）；`exitEdit` 同款对称恢复；`focusEditorAt` 改 `focus({preventScroll:true})` 从源头禁 focus 滚动（异步滚动晚于同步代码，事后恢复锁不住）；CSS 给 `.note-textarea` 补 `display:block`（根除基线空隙）、`padding:0`（度量对齐），并按 `.note-confirm[hidden]` 同款教训补 `.note-textarea[hidden]{display:none}`（display:block 会压过 hidden 的 UA 样式，漏补会让编辑框常驻占位）。

**验证**（harness 全场景回归，滚动位置逐字节留痕）：fresh 布局健全（scrollH 1280/textH 1260/ta display none）；中部滚动 400 点击 offset 565——trace 全程 400、光标 565、Enter 退出 delta 0；底部 594 点击 offset 1700——trace 全程 594、Enter 退出 delta 0。复现材料仍在 `%TEMP%\bugzia-caret-debug\`。注意：前端 go:embed 编译期打包，改动需重编译才生效。

## 透明垫白根因修正（上一节结论证伪，Win32/DWM/COM 层）

> 创建于 2026-11-17 16:25

**需求**：「透明窗口漂白修复」节（10:58 补记）落地后，开发者实测降低 bg_alpha 便签仍被垫白（调低不透明度时颜色发白），上一节「ExStyle 覆盖去掉 NOREDIRECTIONBITMAP + blur-behind」的修复组合被证伪，须找到真根因。

**根因链（像素级采样逐层定位，每步与理论混合值精确对账）**：

1. 前端（note.js rgba 注入）与数据链（settings.js → settingsui → wm.Hydrate）全程 rgb 与 a 独立、无数值耦合，排除应用层；全项目无第二道窗口级 alpha（无 SetLayeredWindowAttributes）。
2. 像素取证法：隐藏便签采背景、显示采前景、逐点解有效 alpha。实测便签区域颜色 = rgba(bg_r,bg_g,bg_b,α) 与**纯白**的精确混合值（α=0.5 时 (228,171,187)、α=0.3 时 (239,205,214)、α=0.6 时 (223,155,173)，三组均与理论值对账到 ±1），而便签背后实为深色 IDE (33,37,43)——内容 alpha 正确、混合背景被强制为白。
3. 对照 bugzia 参考栈（tao 0.35.3/wry 0.55.1/webview2-com 0.38.2，Cargo.lock 同版本）逐层比对：窗口样式（无 NORDB + blur-behind）我们后来一致；wry 的 controller 创建（Environment10 → CreateCoreWebView2ControllerOptions → ControllerOptions3::SetDefaultBackgroundColor(α=0) → CreateCoreWebView2ControllerWithOptions，wry mod.rs:398-408）与已有补丁一致；GUID/vtbl 槽位逐一对 webview2-com-sys 0.38.2 核实无误；运行日志确认透明路径生效——但垫白依旧。
4. **真根因（两处叠加，均已修）**：① Wails 对「无边框 + 未禁用装饰」窗口调用 `DwmExtendFrameIntoClientArea`（MARGINS{1,1,1,1}，WM_ACTIVATE 等五处调用点），给窗口垫 DWM 玻璃底，alpha-aware WebView 的半透明内容混在这层白底上——tao 全程从不调此 API（grep 证伪「tao 也调」的猜测）；② 透明窗口须走 Wails 原生 `WS_EX_NOREDIRECTIONBITMAP` 路径（无重定向面，alpha 直通 DWM），上一节「去掉 NORDB + blur-behind」的 tao 风格改造在 Wails 窗口链路下仍垫白，已整体回退。10:58 节「NOREDIRECTIONBITMAP=垫白根因」的结论系当时 controller 尚非 alpha-aware 所致的误判，以本节为准。

**实施**：

- `.wails-patched/.../webview_window_windows.go` `framelessWithDecorations()`：`BackgroundTypeTransparent` 直接返回 false（五处扩边调用点全部跳过；边缘缩放等其余功能不经过此函数，无回归面）
- `main.go` CreateNoteWindow：删除 `Windows.ExStyle` 覆盖与 `winutil.SetBlurBehind` 接线，回归 Wails 原生透明路径（NOREDIRECTIONBITMAP + alpha-aware controller）
- `internal/winutil/`：删除已无调用方的 `SetBlurBehind`/`dwmBlurBehind` 及 dwmapi/gdi32 proc 绑定（其注释含已被证伪的旧结论，一并移除）；`winutil_other.go` 同步删桩
- `.wails-patched/.../edge/chromium.go`：透明路径失败回退补日志（capability 静默回退曾是排查盲区）；成功路径诊断日志裁撤
- 附带核实：`.wails-patched` COM 补丁（Environment10/ControllerOptions3）GUID 与槽位最终确认无误，维持不变

**验证**：`go build/vet/test` 全过；像素取证三组 α 值对账吻合后，修复组合经开发者实机目视确认生效（16:2x 口头确认「可以了」）。测量期间干扰源记录：全屏视频（硬件叠加层令屏幕采样失效）、便签最小化态（SW_SHOWNA 不恢复最小化，须 SW_RESTORE）、用户热键切隐藏、WindowRect 含 DWM 阴影边、未钉便签 SetBottom 后 z 序低于壁纸层——复测时须逐一排除。

**根因**（playwright 有头复现页实测证实）：`syncTextareaHeight` 首轮测量发生在 body 无滚动条的布局下（测量瞬间 ta 仅 min-height:100%，撑不出滚动条），换行宽度比最终态宽（实测 216px vs 201px），测得高度偏小（8506px vs 实际 9199px）；赋高后内容超屏、body 滚动条出现、宽度收窄、文本重排变高，超出部分被 ta 的 `overflow:hidden` 裁掉且 body 最大滚动距离只到 ta 盒高，被裁尾部永久不可达——内容刚好超屏一两行时被裁的正是末行。无头浏览器（overlay 滚动条占宽 0）不触发，Windows WebView2 经典滚动条占宽触发。bugzia 参考实现同构同病，无现成解法可抄。

**实施**：`frontend/assets/note.js` `syncTextareaHeight` 改为迭代收敛——赋高后再测 `scrollHeight`，若变化则再赋，上限 3 轮（滚动条只有出现/消失两个状态，两轮内必收敛）；零视觉/交互变化。备选未采纳：`scrollbar-gutter: stable`（右侧恒定 15px 留白）、隐藏滚动条（失去拖拽）——均改外观/交互，不夹带进 bug 修复。

**验证**：复现页对照实验——修复前 clippedTail=693px、末行不可达；修复后 clippedTail=0、endReachable=true，短内容（不足一屏）无回归；`go build/vet/test` 全过；实机手测待开发者确认。
