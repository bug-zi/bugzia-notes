# bugzia-notes 设计 — v4.3.0 退出时自动销毁空便签

> 创建于 2026-11-27 00:21（会话需求确认）。维护权责见 `docs/project/README.md`。
> 前置：v4.2.1（已发布）。全局设置不涉及。

## 1. 背景与目标

退出应用后，编辑过又清空的、新建后没用过的便签会一直留着，重启后一批空便签很乱。目标（会话确认）：**退出应用时自动销毁全部空便签**。

## 2. 语义（会话确认）

1. **空** = 无文字且无图片：`strings.TrimSpace(Content) == ""`——全空白行/空白字符也算空；图片 token 行（`![img](picture/<名>)`）本身非空字符串，天然保留。
2. **范围**：辅助便签（slot 1~5）与自由便签（slot -1）；**主便签（slot 0，待办事项）永不销毁**——与 v4.0.0 不可销毁语义一致，即使主便签 content 为空也不动（启动恢复还会补建）。
3. 置顶（Pinned）/钉住（Fixed）/样式锁定的空便签**照常销毁**——仅看内容，不看层级/保护状态（会话确认）。
4. **静默销毁**：无确认弹窗；不入回收站（空便签本就不满足「非空入站」条件，与既有 `ConfirmDestroy` 语义一致）。
5. 隐藏的空自由便签（如召唤后没写字又收起的）同样清理——空即无数据损失，规则简单可预期。

## 3. 实现

1. **`Controller.DestroyEmptyNotes() int`**（internal/wm/controller.go）：锁内遍历权威列表，收集 `slot != model.SlotMain && strings.TrimSpace(rec.Content) == ""` 的便签 → 逐张从列表移除 + `ops.CloseNote(id)` 关窗 → 既有 `scheduleSave` 防抖落盘（与销毁链同入口）→ 返回清理张数。窗口在退出流程中即将随进程结束，关窗仅为状态一致性（防极端时序下窗口残留）。
2. **main.go 退出清理段接线**：`app.Run()` 返回后、`st.Close()` 之前插入 `ctl.DestroyEmptyNotes()`，清理数记日志（`log.Printf("[exit] 已清理空便签 %d 张")`，0 张不打印）。顺序保证：`DestroyEmptyNotes` 的 `scheduleSave`（400ms 防抖 timer）由随后 `st.Close()` → `flushNotes` 立即落盘。
3. **退出路径覆盖**：托盘「退出」（`app.Quit`）与自更新重启（`applyUpdate` → `app.Quit`）都汇入 `app.Run()` 返回后的同一段清理，天然全覆盖；杀进程/崩溃不走此路径，便签下次启动原样恢复（无影响）。
4. 否决的替代：启动时清理（语义不符——需求是退出时机）；前端「清空即销毁」（变成编辑清空立即删便签，语义不符）。

## 4. 测试

1. Go 单测（WindowOps 内存替身，同 `ConfirmDestroy` 测试模式）：
   - 空辅助便签销毁（关窗调用 + 列表移除 + Count 减少）；
   - 空自由便签销毁；
   - 主便签 content 为空不销毁；
   - 有文字/有图片 token 行的便签不销毁；
   - 仅空白行（`"\n \n"`）销毁；
   - 钉住+置顶+样式锁定的空便签照常销毁；
   - 全部非空时返回 0、列表不动。
2. 手测闸口：托盘退出 → 空便签消失、有内容便签保留；重启后不复活；主便签（含空待办）仍在；自更新重启路径空便签同样被清；带图/带字便签退出后原样恢复。
