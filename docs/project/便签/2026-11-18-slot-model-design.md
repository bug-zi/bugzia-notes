# bugzia-notes 设计 — 6 槽位便签模型（1 主 + 5 辅）

介绍：把自由便签列表（上限 50、随意新建）重构为 6 个固定槽位——1 张主便签（常用常更新，`alt+c` 管理）+ 5 张辅助便签（不常用，需要多便签时才召唤，`alt+1`~`alt+5` 各管一张、各一色）。集合切换（`alt+n`）与销毁当前（`alt+z`）保留。

- 状态：草稿待开发者审核（brainstorming 产出 2026-11-18）
- 依据：v1 主体设计（`../全局/archive/2026-11-16-bugzia-notes-app-design.md`）+ 便签独立样式锁设计（`2026-11-17-per-note-style-lock-design.md`）
- 关联需求来源：开发者 2026-11-18 会话直接提出（主便签 + 5 辅助便签分键管理、五色区分、5 个足够）

## 1. 背景与目标

现状：应用是自由便签列表（`alt+shift+c` 随意新建、上限 50 张、`alt+n` 整体显隐、`alt+z` 销毁当前），所有便签共用全局默认样式（样式锁可单张独立）。

目标：

- 交互模型收敛为 6 个固定槽位：主便签（Slot 0）+ 辅助便签 1~5（Slot 1~5）
- 6 键统一切换式：对应槽位无便签→创建并显示聚焦；隐藏→显示聚焦；已显示→隐藏
- 辅助便签各有预设底色（与玫红同源柔和色系），设置窗口可改；主便签跟随全局默认样式
- `alt+n` 集合切换、`alt+z` 销毁当前（含 Y/N 确认与回收站）保留，语义不变
- 老数据平滑升级：最近更新的自由便签升级为主便签，其余不加载（备份留存）

## 2. 非目标

- 不做槽位增减（固定 1+5，不提供「再来一个槽位」）
- 不做槽位重命名/备注功能
- 不改便签窗口的编辑/IME/拖动/缩放/复制等既有交互
- 不做非 Windows 平台适配调优（现有约束照旧）
- 不迁移 bugzia 的 summon 键（与现状一致：summon 属输入条不属于便签）
- 不提供「槽位排序/换色批量操作」（逐槽在设置里改色即可）

## 3. 已批准决策（会话确认）

| 决策点 | 结论 |
|---|---|
| 与自由便签系统的关系 | **全面取代**：应用即 6 槽位，去掉自由新建与 50 张上限 |
| 六键行为 | **统一切换式**（建/显/隐三态），主辅一致 |
| `alt+n` 集合切换 | 保留，语义不变（全部显示/隐藏） |
| `alt+z` 销毁当前 | 保留，语义不变（Y/N 确认；非空内容进回收站；槽位清空待下次创建） |
| 辅助五色 | **预设 5 色 + 设置窗口可改**；默认色值见 §7 |
| 主便签样式 | 跟随全局默认（设置可改，现状机制不变）；样式锁保留可用 |
| 辅助便签样式锁 | **禁用**：辅助便签底色唯一来源 = 槽位色设置；前端隐藏样式锁入口 |
| 老数据迁移 | 最近更新的一张→主便签（全字段保留），其余不加载；原 notes.json 改名备份留存 |
| 主便签首启 | **全新安装首启自动创建**（静默启动预建隐藏）；主便签被销毁后重启同样自动恢复空白主便签 |
| 默认键位 | `alt+n` / `alt+c` / `alt+z` / `alt+1`~`alt+5` |
| 实现方案 | **槽位作为便签属性**（NoteRecord 加 Slot 字段），复用现有窗口/事件/装箱/防抖/回收站全部机制 |

## 4. 领域模型（槽位）

- `NoteRecord.Slot int`（`json:"slot"`）：0 = 主便签，1~5 = 辅助便签。常量 `SlotMain = 0`
- 槽位唯一性：控制器保证每槽位至多一张；总便签数天然 ≤6（`MaxNotes` 50→6，语义 = 槽位上限）
- 槽位身份随记录持久化，重启即恢复（谁在哪个槽位、内容、几何、钉住态全部照旧）
- 窗口 Name/Title = 便签 id 的约定不变（槽位不影响窗口标识）

## 5. 数据与存储升级

### 5.1 notes.json v1 → v2

- 文件形状加版本判定：v1（记录无 slot）→ 迁移；v2 直接读
- 迁移规则：取 `UpdatedAt` 最大的一条设 `Slot=0`（内容/几何/样式锁/钉住态全保留），**其余记录不加载**
- 原文件改名 `notes.json.bak-YYYYMMDD-HHMMSS` 留存（不删）；迁移后立即以 v2 形状落盘
- 损坏回退空表现状不变（损坏文件无从迁移，走现有损坏处理）
- 旧数据目录一次性迁移（`migrateLegacyDataDir`）与控制器导入路径涉及的老记录同样遵循「最新→主便签」规则分配槽位

### 5.2 settings.json v1 → v2

- `HotkeySettings` 增加 `Main`、`Aux1`~`Aux5` 六个字段（json：`main`、`aux1`..`aux5`）；`Settings` 增加 `AuxColors [5]{R,G,B}`（json：`aux_colors`）
- v1 → v2 升级规则（读文件时按版本判定，只做一次）：`Main` 继承老 `create` 值（含空=禁用，尊重用户原选择）；`Aux1`~`Aux5` 填默认 `alt+1`~`alt+5`；`AuxColors` 填默认五色
- v2 文件完全信任文件值（留空 = 禁用是合法状态，不再补默认）
- 全新安装（无 settings.json）：`DefaultSettings()` 直接给出 8 键默认 + 五色

### 5.3 默认值

- `DefaultSettings()` 键位：`toggle=alt+n`、`main=alt+c`、`destroy_current=alt+z`、`aux1..5=alt+1..alt+5`
- 默认五色（白字可读性已校准，与玫红 #C95877 同源柔和系）：

## 6. 快捷键体系（3 键 → 8 键）

- id 表：1=集合切换（`IDToggle` 不变）、2=主便签（原 `IDCreate` 改名 `IDMain`、语义改为召唤主便签）、3=销毁当前（`IDKill` 不变）、4~8=辅助便签 1~5（新增 `IDAux1`~`IDAux5`）
- `hotkey.Label` 更新：集合切换 / 主便签 / 销毁当前 / 辅助便签 1~5
- `ParseAll` 扩到 8 条：查重、留空=禁用、逐键注册 + 冲突降级（被占用键跳过并报告、其余照常生效）机制全部照旧；`vkNames` 已支持 `0-9` 主键，无需扩展
- `dispatchHotkey`：`IDMain` → `ToggleSlot(0)`；`IDAux1..5` → `ToggleSlot(1..5)`
- bugzia 配置迁移映射调整：bugzia `create` 键 → 本应用 `Main`（沿用用户在 bugzia 的习惯键）；toggle/destroy 映射不变；样式默认迁移不变
- `alt+1`~`alt+5` 属高频易冲突组合（输入法、游戏、其他工具），冲突降级 + 冲突报告机制覆盖，不做特殊处理

## 7. 交互语义

### 7.1 ToggleSlot（六键统一）

`ToggleSlot(slot)`，对应槽位便签三态：

1. 槽位无便签 → 创建：空内容、全局默认 W/H、即钉住（新建即钉住保证可见，沿用既有结论）、装箱定位；显示 + 聚焦，成为当前便签
2. 有便签且隐藏 → 显示 + 聚焦，成为当前便签（activeID 更新）
3. 有便签且已显示 → 隐藏（不改 activeID；隐藏当前便签后 `alt+z` 仍指向它，`RequestDestroy` 会先显示再确认，行为自洽）

### 7.2 主便签常驻

- 启动恢复（`Start`/`StartHidden`）时若**无 Slot=0 记录**则自动补建主便签（全新安装、主便签被 `alt+z` 销毁后重启、备份恢复缺主便签等场景统一覆盖）；辅助便签存在与否不影响补建
- 静默启动同样预建隐藏（召唤零延迟）

### 7.3 集合切换与销毁（不变项）

- `alt+n`：判断展开态只认「pinned 且可见」；召唤时 unpinned 升级 pinned（防空转）——全部沿用
- `alt+z`：销毁「当前便签」（最近新建/编辑，回退列表最后一张），Y/N 确认，非空内容进回收站；销毁后槽位清空，下次按键按 §7.1 重新创建
- 回收站机制（recycle.json）不变，辅助便签销毁同样进

### 7.4 托盘

- 托盘现状为「回收站 / 设置 / 退出」（2026-11-18 回收站轮次已精简，无便签类入口）；新增「召唤主便签」一项置于「回收站」之前（`ToggleSlot(0)`）
- 其余项保留；不加槽位子菜单（六键已覆盖）

## 8. 样式组合

`EffectiveStyle(record, settings)` 优先级链：

1. `rec.Style != nil`（仅主便签可能，样式锁）→ 完全用锁定快照
2. `rec.Slot >= 1` 且无锁 → 背景色 = `AuxColors[rec.Slot-1]`，圆角/字号/透明度跟随全局
3. 其余（主便签未锁定）→ 完全跟随全局默认

- 全局默认的背景色改动只影响主便签（辅助便签背景恒被槽位色覆盖）；圆角/字号/透明度/默认尺寸改动影响所有便签（锁外字段）
- 辅助便签禁用样式锁：前端按 slot 隐藏便签工具栏「设置」按钮（Hydrate 载荷新增 slot 字段）；控制器 `SetNoteStyleLock`/`ApplyNoteStyleFor` 对 `slot >= 1` 拒绝并报错（纵深防御）
- 主便签样式锁交互不变（面板复用现有锁模型）

## 9. 设置窗口 UI

- 键位区：3 行 → 8 行（集合切换 / 主便签 / 销毁当前 / 辅助便签 1~5），应用流程沿用 `ApplyHotkeys`（解析 8 键、逐键注册、冲突报告、落盘）
- 新增「辅助便签颜色」区：5 个取色器（`<input type="color">`）；改动经新服务方法 `ApplyAuxColors` 实时生效（对已存在的辅助便签重推 Hydrate）并落盘；值经 clamp 后写入
- 「样式默认」区保留，语义微调：背景色作用于主便签；圆角/字号/透明度/默认尺寸作用于全体便签（说明文案随之微调）
- 修改后重新 `wails3 generate bindings`

## 10. 错误处理与边界

- 键位冲突：逐键降级 + 冲突名单报告（现状机制），不整体失败
- notes.json 迁移失败（IO 错误）：原文件不动、按空表启动并记日志（不静默丢数据；备份命名冲突时追加序号）
- settings.json v1→v2 写盘失败：内存态已升级（本次会话生效），下次启动重试迁移（版本判定保证幂等）
- 单实例、自启动自愈、静默启动、数据目录迁移等既有机制不受影响

## 11. 测试策略

单测（go test）：

- notes v1→v2 迁移：多张自由便签 → 最新为主便签（字段全保留）、其余不加载、备份文件存在、幂等（二次加载不重复迁移）
- settings v1→v2：create→main 继承（含空值）、aux 键与五色补默认、v2 文件不覆盖用户显式值
- `ToggleSlot` 三态（建/显/隐）、槽位唯一性、创建即钉住、显示分支更新 activeID
- 销毁后槽位清空；启动时主便签缺失自动补建（含销毁主便签但保留辅助便签的场景）
- `EffectiveStyle` 三级优先：主便签锁 > 辅助槽位色 > 全局；`AuxColors` 改动对已存在辅助便签生效
- 样式锁对辅助便签拒绝（控制器层）
- `ParseAll` 8 键解析与查重、`Label` 文案
- bugzia 迁移映射 create→main

手测闸口（本 spec 落地时按此验收）：

1. 全新配置目录启动：主便签自动出现；`alt+c` 显隐切换正常
2. `alt+1`~`alt+5`：各自创建、五色正确、显隐切换、编辑/IME/失焦提交
3. `alt+n` 集合切换不空转；`alt+z` 确认销毁（按钮/Y/N/回收站）
4. 升级场景：v1 notes.json → 主便签保留（内容/位置/样式锁）、备份文件存在、其余不加载
5. 设置窗口：改键位（含故意制造冲突）实时生效并报告；改辅助色实时生效
6. 主便签样式锁可用；辅助便签无「设置」按钮
7. 静默启动（自启动路径）：主便签预建隐藏，`alt+c` 召唤零延迟
