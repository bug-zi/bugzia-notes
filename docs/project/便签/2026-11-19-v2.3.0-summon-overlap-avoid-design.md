# bugzia-notes 设计 — v2.3.0 召唤智能避重叠

> 创建于 2026-11-19（会话需求确认）。维护权责见 `docs/project/README.md`。
> 前置：`2026-11-19-v2.2.1-changelog-popup-design.md`（已验收）。

## 1. 背景与目标

现状：隐藏便签被召唤（Show）时原位显示。若召唤前其他便签（新建装箱、用户拖动、其他召唤）已占据该位置，被召唤的便签会压在别人下面或被别人盖住，需要手动翻找。v2.3.0 让召唤具备智能避重叠：优先原位，被占则找空位，无空位才原位叠放并保证在最上层。

## 2. 行为规则（会话确认）

召唤一张隐藏便签时，窗口显示前按序判定：

1. **原位置无重叠** → 位置不动，直接显示（现状行为）。
2. **原位置被占，桌面有空位** → 用 `PackTopLeft` 对「当前全部可见兄弟便签矩形」左上装箱扫描；落点复核不与任何可见便签重叠则移动到该处显示（复核用于识别屏幕已满：PackTopLeft 无空位时回退返回左上锚点，该锚点可能重叠）。
3. **原位置被占且无空位** → 位置不动，原位显示；最上层由现有机制保证（召唤便签钉住 TOPMOST + Focus 提到最前）。

判定口径：

- 「重叠」= 矩形任意像素相交。
- 障碍物 = **可见**便签（隐藏便签不占桌面空间）；自身排除。
- 便签位置：实时 `px/py` 优先，未摆放过回退 `rec.X/Y`（与 `packPos` 同规则，负坐标合法）。
- 「桌面」= 主屏逻辑尺寸（`PrimaryScreen`），与现有装箱一致；不管应用程序窗口。

## 3. 生效入口与边界（会话确认）

- **三个召唤入口统一**：`ToggleSlot`（辅助 alt+1~5）、`ToggleMainSet`（集合切换 alt+n）、`CreateOrSummonFree`（新建键 alt+c 的召唤分支）——收敛为共用召唤助手，三处调用。
- 集合切换多张连召**逐张处理**：先召唤者的落位（含避让后新位置）成为后召唤者的障碍。
- 不参与的部分：
  - 已显示便签（只管隐藏→显示的召唤）。
  - `alt+z` 销毁确认的显示（`RequestDestroy`）：临时确认态，Focus 已保证可交互，不走避让。
  - 升钉（`ToggleMainSet` promote 分支）：只改层级不动位置。
- 情况 3 置顶保证的边界：召唤便签为**钉住态**时成立（Show 激活即 TOPMOST 带内置前 + Focus 兜底；召唤路径的便签创建即钉、集合切换升钉，常态都满足）。**未钉**便签维持沉底语义（`HWND_BOTTOM`）不为例外放行——重叠方也未钉时按显示顺序天然在上；重叠方钉住时未钉方在其下，属未钉语义的正常表现，不为避重叠破坏「未钉不遮应用窗口」的全局设计。
- 聚焦规则维持现状：单召唤入口（`ToggleSlot` / `CreateOrSummonFree`）聚焦被召唤便签；集合切换只聚焦 UpdatedAt 最大者，其余只显示不抢焦点。
- **哨兵语义不变**：避让位移是程序性摆放，不写 `rec.X/Y`，只更新 `px/py`；下次召唤重新判定，幂等。

## 4. 变更清单

- `internal/wm/controller.go`：
  - 新增召唤助手（内部方法）：判定三情况 → 必要时 `MoveNote` → Show →（聚焦时）Focus + 记 activeID。单召唤入口（`ToggleSlot` / `CreateOrSummonFree`）整单走助手；`ToggleMainSet` 召唤分支对每张隐藏成员走助手（不逐张聚焦），焦点仍只在 UpdatedAt 最大者（现行规则）。
  - 重叠判定用小工具函数（矩形相交测试，可单测）。
- `WindowOps` 接口 + `main.go`（wailsOps）：
  - 新增 `MoveNote(id string, x, y int)`：移动既有便签窗口（`SetPosition`）。
  - **程序性移动防误记**：现有 `WindowDidMove` → `NoteMoved` 把任何移动当用户拖动（写 `rec.X/Y` + 刷 `UpdatedAt`）。`MoveNote` 移动前置抑制标记，事件回调见标记则跳过 `NoteMoved`；`SetPosition` 返回后标记仍在（事件未触发，如坐标未变）兜底清除——否则下次真实拖动会被吞。
  - 判定与移动都发生在窗口隐藏状态（Show 之前），无可见跳动。
- `internal/settingsui/service.go`：`Version` → v2.3.0。
- `frontend/assets/changelog.js`：补 v2.3.0 条目。
- 测试：`internal/wm/controller_test.go` / `layout_test.go` 补充（见 §6）。

## 5. 数据与持久化

无数据形状变化（notes.json 仍 v3、settings.json 仍 v2）。避让只影响运行时摆放：`rec.X/Y` 哨兵语义、`UpdatedAt`、`activeID` 语义全部不变。

## 6. 测试

单测（fakeOps 扩展 `MoveNote` 记录调用）：

- 情况 1：原位无可见兄弟重叠 → 不调 `MoveNote`，原位显示。
- 情况 2：原位被可见兄弟占据 → `MoveNote` 到装箱落点（不重叠），`px/py` 更新、`rec.X/Y` 不变、`UpdatedAt` 不刷。
- 情况 3：屏幕被可见兄弟铺满（装箱回退点重叠）→ 不调 `MoveNote`，原位显示。
- 多张连召：两张隐藏便签同被占区 → 第一张落位后，第二张的障碍含第一张新位置。
- 负坐标原位参与重叠判定。
- 隐藏兄弟不算障碍：原位与隐藏便签重叠 → 情况 1。
- 矩形相交工具函数：相交 / 相邻不交 / 包含 / 空集。

手测闸口（三入口 × 三情况）：

1. 辅助键（alt+1~5）：原位空召唤原位；原位被新建便签盖住召唤到空位；铺满屏幕召唤原位置顶。
2. 集合切换（alt+n）：多张隐藏便签连召逐张避让，互不叠（除非原位互叠）。
3. 新建键（alt+c）召唤隐藏自由便签同规则。
4. 避让位移后拖动该便签，重启后恢复拖动位置（哨兵语义未破坏）。
5. `go build ./...` + `go vet ./...` + `go test ./...` 全绿。
