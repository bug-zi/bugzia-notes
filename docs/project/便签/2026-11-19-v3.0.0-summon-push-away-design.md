# bugzia-notes 设计 — v3.0.0 召唤弹开式避重叠

> 创建于 2026-11-19（会话需求确认）。维护权责见 `docs/project/README.md`。
> 前置：`2026-11-19-v2.3.0-summon-overlap-avoid-design.md`（已验收发布）。

## 1. 背景与目标

v2.3.0 的避重叠是「召唤者让位」：原位被占时召唤便签自己装箱找空位。实践后开发者提出两点：其一，实测部分重叠场景未触发避让（只有大部分重叠才生效）——检测层疑似有 bug；其二，期望的行为模型反转：**召唤便签固定原位出现，把挡路的便签「弹开」**，弹开带动画、尽可能自然。目标不变量：召唤动作完成后，被召唤便签与「召唤前已可见」的便签之间完全不重叠。

## 2. 行为规则（会话确认）

召唤便签 0 时（三入口统一：`ToggleSlot` / `ToggleMainSet` / `CreateOrSummonFree`）：

1. **被召唤便签原位落地**（v2.3.0 的「召唤者自己找位置」删除），可交互、置顶（钉住 TOPMOST + Focus 现有机制）。落地后可能被**更高优先级**（更活跃）的批内召唤便签弹开——见规则 4。
2. 计算「**召唤前已可见**且与便签 0 矩形相交」的便签集合，逐张弹开：
   - 候选方向 右 / 下 / 左 / 上，各自算「消除与推入者相交」的最小位移；落点约束：留 8px 间隙（`PlaceMargin` 同源）、完整在主屏内；**取可行方向中位移最小者**（大小相同偏向右/下）。
   - 四方向均不可行 → **被弹者装箱找空位**（`PackTopLeft` 对其余可见兄弟 + 落点复核，即 v2.3.0 逻辑用在被弹者身上）。
   - 装箱也无空位（屏幕满）→ 接受重叠，被弹者原地不动，便签 0 置顶可交互。
3. **级联**：被弹者落点若与别的已可见便签相交 → 继续弹开那张（同规则），深度上限 = 便签总数（防循环）；已在本轮处理过的便签不重复作为弹开目标。
4. **不可推动集合（所有入口统一）**= {当前正在落地的这张召唤便签}——每张被召唤便签**原位落地 + 弹开一切与之相交的当前已可见便签**（含批次前已可见的、含批内已落地的）。
   - 集合切换连召：批次按 **UpdatedAt 升序**逐张落地（最不活跃的先落地，最活跃的最后落地）——最终最活跃者必保原位（它落地时推别人、之后无人再推它），久未动的被逐步弹开，与「活跃度高者保原位」意图一致；焦点目标（UpdatedAt 最大者）即最后落地者，语义自洽。
   - 「最大限度平摊开不重叠」由兜底链保证：弹开（推向空处）→ 装箱找空位 → 屏幕真放不下才接受重叠。
5. 手动拖动造成的重叠不受干预（用户意图优先）；下次召唤动作才消解。

## 3. 持久化（会话确认）

- 被弹者落点写实时 `px/py`。
- `rec.X/Y` 已非哨兵（用户摆放过）→ 同步写 rec.X/Y（**弹后位置记住**，重启恢复所见即所得）。
- 哨兵便签（从未手动摆放）不写 rec，保持哨兵语义（重启重新装箱时按兄弟实时位置避让，自愈不叠）。
- 弹开是系统行为：**不刷 UpdatedAt**、不改 activeID；整批完成后统一一次防抖落盘。

## 4. 动画

- `WindowOps` 新增 `GlideNote(id string, x, y int, ms int)`：wailsOps 实现 Go 侧步进 tween——读当前实际位置 → ~250ms ease-out（三次方）→ 每 ~16ms 一步 `SetPosition` → 落点精确到位。
- **状态先写、动画纯视觉追赶**：pushPass 同步解析并立即写入 `px/py` / `rec`（防抖落盘），动画只是把窗口视觉位置滑向已确定的最终位——这样连召场景后一张的推送计算读到的一定是最终几何，不存在读到动画中途位置的问题。
- 同一窗口再次 `GlideNote`（快速连按/连召）→ 取消该窗口进行中的旧 tween，从当前视觉位置重新起滑到新目标。
- 多张被弹时每张错开 ~40ms 启动（瀑布感）；动画时长参数化（单测传 0 直落）。
- 全程抑制该窗口 `WindowDidMove` 记账：`suppressMove` 所有权改为「动画/移动持有者负责置位与结束清除，事件回调只读跳过不删」；`MoveNote` 同步调整为此模式（结束时标记仍在且无动画进行 → 兜底清除，防吞后续真实拖动）。
- 动画中途进程退出：状态已落定（先写），重启按恢复语义走，无一致性问题。

## 5. 技术结构

- **纯函数核心**（`internal/wm/` 新文件或 layout.go 扩展）：`ResolveOverlaps(self Rect, siblings []Rect, immovable map[string]bool) → []Push`（Push = 便签标识 + 目标位置 + 方式{弹开/装箱/接受重叠}）。级联、换向、兜底全部在纯函数内解析——可穷尽单测。
- 三入口 `summonNote` 改为「原位落地 + pushPass」；`ToggleMainSet` 将召唤批次按 UpdatedAt **升序**排列后逐张处理（每张的不可推集合 = 该张自身）。
- 判定复用 `rectsIntersect`；坐标全部 DIP 逻辑像素（与装箱一致）。
- **几何正确性（开发者明示注意点）**：便签位置与大小都可实时变动——所有几何输入一律取实时值：位置 = `px/py`（实时优先、rec 兜底），尺寸 = `model.ClampW/ClampH(rec.W/H)`（NoteResized 同步后的当前值）。`ResolveOverlaps` 必须接收每张便签的独立尺寸，位移量、方向可行性（能否完整落进屏幕）、级联落点判定全部按真实尺寸计算，任何环节不得假尺寸。尺寸超过屏幕的便签：四方向均不可行 → 装箱也放不下 → 接受重叠，兜底链自然终止不死循环。
- **Phase 0（先行任务，会话确认纳入本版）**：v2.3.0 实测「部分重叠未触发避让」——`rectsIntersect` 数学上任何像素相交都应命中，疑似拖动结束后 `px/py` 与窗口真实位置存在细小偏差（`WindowDidMove` 末次事件滞后/丢失）。先用现有 `[summon]` 日志取证（复现部分重叠场景），必要时临时加矩形 dump（含 W/H，同时核实尺寸同步——`WindowDidResize` 末次事件是否有同样的滞后）；确认根因并修复——检测层是弹开的同一入口，不修好弹开同样失灵。修复的回归单测属本版范围。

## 6. 数据与持久化

无数据形状变化（notes.json 仍 v3、settings.json 仍 v2）。被弹者的 rec.X/Y 更新复用现有字段，无迁移。

## 7. 测试

单测：

- `ResolveOverlaps`：右/下/左/上方向选择（最小位移）、四向出屏 → 装箱兜底、装箱无空位 → 接受重叠、级联链、级联撞不可推者换向、循环防护（深度上限）、间隙 8px、多张同时弹开。
- 连召互推：批次 UpdatedAt 升序落地（最活跃者最后落地、必保原位）；批内互叠时低活跃者被弹开；批内放不下走装箱兜底、屏幕满才重叠。
- 动画：fakeOps 扩展记录 `GlideNote` 目标位；ms=0 直落路径。
- 持久化：placed 被弹者 rec.X/Y 更新、哨兵被弹者 rec 不变、UpdatedAt 不刷、一次防抖落盘。
- Phase 0 修复的回归单测（视根因而定）。

手测闸口：

1. 单召唤（三入口）：重叠便签被弹开，动画自然（ease-out、瀑布错开），便签 0 原位不动。
2. 级联：被弹者撞第三张时传导弹开；撞不可推者时换向/兜底。
3. 四向都弹不出屏：被弹者装箱找空位；铺满屏幕接受重叠、0 置顶。
4. 集合切换连召：批次按 UpdatedAt 升序逐张落地，最活跃者最后落地且保原位；互叠者被逐步弹开、最大限度平摊开，放不下才重叠。
5. **部分重叠场景触发**（Phase 0 验证点）。
6. 弹后重启：placed 便签恢复弹后位置；哨兵便签重装箱不叠。
7. **缩放过便签参与弹开**：按缩放后尺寸计算位移与可行性；缩放到超大（宽高超屏）的便签不引发死循环、按接受重叠兜底。
8. 动画中/后真实拖动与缩放功能正常（抑制不吞事件）。
8. `go build ./...` + `go vet ./...` + `go test ./...` 全绿。
