## 1. 背景与目标

主便签当前是一张普通文本便签（textarea 自由编辑）。目标（开发者提出并经会话确认）：

1. **主便签固定为待办事项列表**：条目化展示，完成打勾即从便签移除，并留痕记录。
2. **记事簿**：托盘右键新增「记事簿」入口，单例窗口查看已完成事项及完成时间（格式 `261121-11:25`）。
3. **分类**：主便签按分类分区展示（如【日常】【作业】），分类可在主便签设置中管理（增/改/移/删/合并），记事簿支持「按时间」与「按分类」两种查看方式。
4. 主便签默认名改为「待办事项」。

范围界定：只有主便签（Slot=0）待办化；辅助便签、自由便签完全不变（仍自由文本）。主便签的钉住/置顶/样式锁/改名等既有能力全部保留，「固定」仅体现为内容形态（分区待办列表）与不可销毁。

## 2. 需求商讨决策记录

| 决策点 | 结论 |
|---|---|
| 主便签编辑形态 | 结构化条目：每条前有可点击勾选框，点框完成、点文字编辑、Enter 新增下一条 |
| 长待办 | 「一行」仅为存储分隔单位；显示自动折行、条目框自适应高、正文区滚动；条目内部无换行符（粘贴多行拆为多条） |
| 记事簿交互 | 只读查看 + 每条「还原」（放回主便签）；不做删除/清空（YAGNI） |
| 留痕容量 | 不设上限，完整保留 |
| 主便签销毁 | 不可销毁（更多菜单不显示销毁项；alt+z 拦截并提示） |
| 存储方案 | 方案 A：content 仍纯文本按行存（notes.json 形状不变），留痕独立 `done.json`；「一行=一条待办、`【已配置分类名】`=分区标题行」；不升级 notes.json 结构（方案 B 结构化 Items 无需求支撑，否决） |
| 分类初始值 | `日常`、`理论学习`、`作业`、`项目开发`、`未分类`（从上往下）；「未分类」固定最后、不可删、不可改名 |
| 分类变更联动 | 改名/合并/删除同步改写便签标题行与留痕记录的分类名（分类是整理维度不是历史事实） |
| 主便签改名 | 默认名「待办事项」；升级时主便签标题为默认样式「便签n」的自动改名（自定义名不动） |
| 记事簿视图 | 「按时间」（默认，全部新到旧平铺）｜「按分类」（按配置顺序分组）双视图切换 |

## 3. 主便签交互（分区条目列表）

### 3.1 阅读态

- 内容按行解析：匹配「`【分类名】` 且分类名存在于配置」的行渲染为**分区标题**；其余非空行为**待办条目**，归属其上方最近的分区标题；第一个标题之前的行与无任何标题时的全部行归属「未分类」。
- 分区按配置顺序渲染（未分类恒最后）；条目 = 勾选框 + 文字，长文字软折行、条目框自适应高度，总高超出便签时正文区滚动（现有机制沿用）。
- 分区标题行在便签内**不可直接编辑**（只能经分类管理改，保证内容与配置同步）。
- 每个分区标题行右侧有 ⊕ 按钮（Material Symbols `add`，inline SVG，同现有锁图标方式）：点击在该分区末尾新增待办并进入编辑；点正文最底部空白 = 给最后一个分区新增。

### 3.2 编辑交互

| 操作 | 行为 |
|---|---|
| 点某条文字 | 该条变编辑框（自动折行），光标定位点击处 |
| 编辑框内 Enter | 提交本条，下方新增一条并进入编辑（连续录入，位置仍在同分区） |
| 编辑框内 Esc | 还原本条，退出编辑 |
| 编辑框失焦 | 提交本条 |
| 编辑成空文字提交 | 删除该条（不产生空条目） |
| 粘贴多行文本 | 按行拆为多条待办 |
| 中文 IME | `isComposing` 时 Enter 不提交（沿用现有 ta 兼容模式） |

提交后发 `note:changed`（现有通道）保存 content；分区标题行不受编辑影响。

### 3.3 打勾

- 点勾选框 → 发 `note:todo-check {id, category, text}` → Go 从 content 对应分区删除首个匹配行 → 记入留痕（§5）→ 单窗重推刷新渲染。前端不本地双写，统一由 Go 重推（单一数据源，防竞态）。
- 同分区内同名多条只移除第一条。

### 3.4 主便签不可销毁

- 「更多」菜单对主便签（slot=0）不渲染「销毁」项（hydrate 载荷已带 slot）。
- `alt+z` / 销毁链路在 Go 侧拦截：目标是主便签时弹系统通知「主便签：待办便签不可销毁」，确认浮层不拉起。
- 复制按钮照旧：复制 content 原样（含标题行）。

## 4. 分类体系与管理

### 4.1 配置数据

- `settings.json` 增量字段 `Settings.TodoCategories []string`（`todo_categories`）；老文件缺该字段回退默认值（零迁移）：`["日常","理论学习","作业","项目开发","未分类"]`。
- 保存校验：名称 rune 截 30、去空白项、去重；**「未分类」强制存在且恒排末尾**（列表中缺失则自动补回；改名不允许以「未分类」为对象）。

### 4.2 分类管理 UI

- 入口：主便签「更多 → 设置」面板，样式区下方新增「分类管理」区（仅主便签显示；辅助/自由便签的设置面板不出现该区）。
- 每行操作：改名（点名字行内编辑，Enter/失焦提交、Esc 还原）、上移、下移、「合并到…」、删除；未分类行无改名/上移/下移/删除/合并出（可作合并目标）。
- 底部「+ 新增分类」：行内输入，追加到「未分类」之前。
- 「合并到…」：点后行内列出其余分类供选定 → 源分类全部待办移入目标分区末尾，源分类删除；「合并为一个新类」= 先合并再改名。
- 任一变更实时生效（§5.3 联动）。

### 4.3 升级迁移（store 层，v4 首启一次性，幂等）

1. 主便签标题匹配默认样式 `^便签\d+$` → 改为「待办事项」（自定义名不动）；就地以 v3 重写 notes.json。
2. 扫描主便签 content 中匹配 `^【(.+)】$` 且不在配置中的名字，自动补进 `todo_categories`（插到「未分类」之前）——防止历史标题行被当普通待办（开发者当前内容与默认五类完全匹配，此规则为保底）。

## 5. 存储与数据流

### 5.1 文件形状

| 文件 | 形状 |
|---|---|
| `notes.json` | **不变（仍 v3）**；主便签 content 按行存（标题行 + 待办行） |
| `settings.json` | 增量字段 `todo_categories`（缺省回退默认五类） |
| `data\done.json` | **新增** `{version:1, entries:[{id,text,category,done_at}]}`：新到旧头插、无上限不裁剪、**立即写盘**（不走防抖）、损坏回退空表（recycle.json 同模式） |

- `DoneEntry.ID` 为随机串（还原按 id 定位，防窗口开着时新条目进来的位置竞态）。
- `done_at` 存 UnixMilli；显示格式 `YYMMDD-HH:MM`（半角冒号，如 `261121-11:25`）。

### 5.2 打勾数据流

1. 前端 `note:todo-check {id, category, text}`；
2. Go 控制器：content 对应分区删该行 → **先 `AddDoneEntry`（done.json 立即落盘）** → 再防抖保存 notes → 单窗重推（复用现有单窗重推通道，同 SetTitle 模式）；
3. 广播 `done:changed`，记事簿窗口若开着即重拉刷新。

**写盘顺序理由**：先留痕后便签。中间断电最坏结果为「条目还在便签 + 留痕已有一条」（再勾一次重复记录，无害），绝不出现「待办无声丢失」。

### 5.3 分类变更联动（Service 统一入口，实时生效）

| 操作 | 主便签 content | done.json 记录 |
|---|---|---|
| 新增 | 「未分类」前插入空分区（无行写入，渲染即可） | 不动 |
| 改名 | 对应标题行改写 | 该分类名记录同步改写 |
| 合并 | 待办行移入目标分区末尾，源标题行删除 | 源分类名记录改为目标类 |
| 删除 | 待办行移入「未分类」末尾，标题行删除 | 该分类名记录改为「未分类」 |

改名/合并/删除后：notes 防抖保存、done.json 立即写盘、主便签单窗重推、广播 `done:changed`、设置窗口与便签面板重拉配置。

### 5.4 还原数据流（记事簿 → 主便签）

1. 记事簿窗口调服务 `RestoreDone(id)`；
2. Go：done.json 删除该条（立即落盘）→ 待办文本插回主便签：**记录的原分类仍在配置中 → 插回该分区末尾；否则插回「未分类」末尾** → notes 防抖保存 → 单窗重推；
3. 广播 `done:changed`；
4. 主便签若处于隐藏状态，**自动召唤**（复用 `summonNote`：置顶显示 + 聚焦）——还原结果当场可见。

## 6. 记事簿窗口

- 托盘菜单：**回收站 / 记事簿 / 设置 / 退出**（记事簿插在回收站之后）。
- 单例窗口（Name="logbook"），`logbook.html` + `logbook-view.js`，回收站窗口同模式；数据经 `settingsui.Service.ListDone()`（Call.ByName，同 ListRecycle）。
- 顶部视图切换（默认「按时间」）：
  - **按时间**：全部记录新到旧平铺，每条 `261121-11:25  内容`，右侧「还原」按钮；
  - **按分类**：按分类配置顺序分组（未分类最后），组内新到旧，条目样式同上；记录中出现已不存在于配置的分类名（理论已被联动改写，兜底场景）归入「未分类」组展示。
- 打开时拉取一次 + 订阅 `done:changed` 实时重拉。
- 配色遵循工程规则 3：主题玫红色系，不引入高饱和撞色。

## 7. 前端改造与事件协议

- `note.js` 按槽位分流：`slot==0` 挂载分区条目列表视图（新模块 `frontend/assets/note-todo.js`，ESM import），隐藏现有 `#text/#ta` 全文视图；`slot>=1` 及自由便签走现有全文编辑，零改动。
- 头部三键、样式面板、更多菜单、销毁确认等公共逻辑完全复用。
- 事件协议（载荷全带 id，防串台）：
  - 前端→Go：`note:todo-check {id, category, text}`（新）；
  - Go→前端：单窗重推（hydrate 通道）、`done:changed`（广播，无 id）。
- 勾选框图标：Material Symbols `check_box` / `check_box_outline_blank`（inline SVG path，同现有 `LOCK_PATH` 方式）。

## 8. 边界与防护

- **不可销毁双拦截**：前端更多菜单不渲染销毁项 + Go 销毁链路（alt+z 与确认回调）拦截。
- **总量上限 20 不变**：主便签固定占一席；startRestore 主便签缺失自动补建逻辑不变（补建标题=「待办事项」）。
- **同名待办**：打勾删首个匹配；还原不查重（同名并存合法）。
- **空分类名/重名**：保存校验拒绝（§4.1）。
- **「未分类」完整性**：校验强制补回末尾，任何操作不可使其消失。
- **done.json 与 notes.json 一致性**：写盘顺序保证宁重复不丢失（§5.2）。
- **Win32 窗口 Title 仍 = id**，改名不影响句柄查找。

## 9. 测试

### 9.1 Go 单测

- **store**：done.json round-trip / 头插保序 / 损坏回退空表 / 无上限不裁剪 / 按 id 删除；settings `todo_categories` 缺省回退默认五类 / round-trip；校验（去空白、去重、未分类补回末尾）。
- **content 解析**：标题行只认已配置分类名；未配置 `【xxx】` 行按普通待办；无标题行内容归「未分类」。
- **控制器打勾流**：分区内删行定位准确、done 头插、防抖落盘；打勾视为编辑（刷 UpdatedAt，与 note:changed 语义一致），除 content 外不动其他字段。
- **控制器还原流**：回原分类末尾 / 原分类已删回未分类 / 主便签隐藏召唤（WindowOps 内存替身）。
- **分类联动**：改名（标题行 + 记录同步改写）/ 合并（待办迁移 + 记录改写）/ 删除（移未分类 + 记录改写）/ 新增顺序 / 未分类强制补回。
- **销毁拦截**：alt+z 路径 + 确认回调路径双拦截。
- **改名迁移**：主便签默认标题「待办事项」；「便签n」自动改名；自定义名不动；历史未知标题行自动补进配置。

### 9.2 手测闸口（全过才算交付）

- 主便签：分区按配置顺序渲染 / 长待办折行与滚动 / 点文字编辑 / Enter 连续录入 / Esc 还原 / 空条删除 / 粘贴多行拆条 / 中文 IME 回车选词不误提交 / 各分区 ⊕ 添加 / 底部空白加末区。
- 打勾：条目移除 + 记事簿即时出现 + 时间格式 `261121-11:25` / 打勾后重启恢复正确。
- 分类管理：新增 / 改名 / 上下移 / 删除（待办入未分类）/ 合并 / 未分类不可删不可改不可移；改名后便签标题行与记事簿记录同步。
- 记事簿：托盘入口 / 单例窗口 / 按时间视图 / 按分类视图切换 / 还原（原分类、已删分类两路）/ 还原时主便签隐藏自动召唤 / 窗口开着实时刷新。
- 不可销毁：更多菜单无销毁项 / alt+z 弹提示且浮层不出现。
- 改名迁移：便签1 → 待办事项 / 重启恢复。
- 回归：辅助、自由便签全文编辑不受影响；集合切换不干涉辅助；配置迁移、单实例、托盘退出；更新日志弹窗。
