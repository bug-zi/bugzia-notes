## 1. 背景与目标

v3.0.0 实现了召唤弹开：召唤便签原位落地、重叠的可见便签被弹开。但手动拖动造成的重叠不受干预（v3.0.0 §2 规则 5），开发者提出升级：**拖动便签 A 压到便签 B/C 时，B/C 被实时「挤开」**——像手推实物一样，被压便签在拖动过程中持续让位，确保便签之间永不重叠。目标不变量：任何拖动/缩放手势结束后，被操作便签与其余可见便签之间不重叠；手势过程中重叠也即时消解、不等到松手。

## 2. 行为规则（会话确认）

1. **触发时机 = 拖动中实时挤开**：拖动/缩放手势进行中，被操作便签 A 的实时矩形每压到一张可见便签，该便签立即动画弹开；A 持续移动则持续再压、被压者持续再让（推实物手感）。不等到松手。
2. **参与范围 = 全部可见便签**：不分钉住/未钉（未钉 A 拖压钉住便签，钉住的也被挤开）；隐藏便签不占桌面、不参与。
3. **缩放同样触发**：拖拽边缘把便签变大压到兄弟便签时，同样实时挤开（移动/缩放同语义）。
4. **被操作便签 A 本身永不程序性位移**，始终跟随鼠标/手势；只弹开别人。
5. 弹开语义与 v3.0.0 完全一致（复用 `ResolveOverlaps` 纯函数）：右/下/左/上取最小位移（间隙 8px、完整在主屏内）→ 四向不可行装箱兜底 → 屏幕满接受重叠；级联自动传导。
6. 被弹者持久化语义与 v3.0.0 相同：实时 `px/py` 更新；placed（非哨兵）同步写 `rec.X/Y`（弹后位置记住）；哨兵保持哨兵；**不刷 UpdatedAt**。
7. `alt+z` 销毁确认等非几何路径不参与；召唤弹开（v3.0.0 三入口）行为不变，自动复用同一 `pushPass`。

## 3. 机制：拖动会话采样（main.go，框架零改动）

**框架事实（已核实源码）**：Windows 上 `WindowDidMove` 是纯 trailing 去抖（默认 50ms，`Windows.WindowDidMoveDebounceMS`）——连续拖动中不触发，停顿/松手后才触发一次；现有 `NoteMoved` 实际语义是「拖动结束记账」。框架另发 `WindowStartMove`/`WindowEndMove`（`WM_ENTERSIZEMOVE`/`WM_EXITSIZEMOVE`）与 `WindowStartResize`/`WindowEndResize`，标记原生手势会话边界。实时挤开因此走会话采样，不改 `.wails-patched`：

- `CreateNoteWindow` 每张便签窗口追加订阅 `events.Windows.WindowStartMove` / `WindowEndMove` / `WindowStartResize` / `WindowEndResize`。
- **Start**（Move 或 Resize）：起采样 goroutine——每窗口至多一个（map 记持有者，重复 Start 先停旧再起新），每 **50ms** 读 `win.Position()` + `win.Size()` → `ctl.DragLiveTick(id, x, y, w, h)`。
- **End**：停 goroutine。最终记账仍走现有去抖 `WindowDidMove/WindowDidResize` → `NoteMoved/NoteResized`（松手 ~50ms 后触发，行为不变）。
- **兜底弹开**：`NoteMoved` / `NoteResized` 记账后各补一次 `pushPass`——覆盖三类会话外场景：松手前最后 50ms 的位移残留重叠、拖动中停顿 >50ms 时的记账点、**Win+方向键贴边等键盘移动**（不走 `WM_ENTERSIZEMOVE`，无 Start/End 事件，只有去抖 `WindowDidMove`）。
- goroutine 退出条件：End 事件，或 tick 时窗口已不存在（`lookup` nil 即退出，防关窗泄漏）；End 与窗口消失双保险。

## 4. 控制器（internal/wm）

- `NoteLive` 增加实时尺寸字段 `rw/rh`（0 = 未置，回退 `ClampW/ClampH(rec.W/H)`）：缩放过程中尺寸实时参与挤开；兄弟便签的几何读取统一改为「实时 `rw/rh` 优先」（顺带修正：召唤弹开读缩放中兄弟的实时尺寸，v3.0.0 只读 rec 值）。
- 新增 `DragLiveTick(id string, x, y, w, h int)`：锁内更新 `px/py` 与 `rw/rh`（w/h>0 才更新尺寸）→ 锁外跑 `pushPass(n)`。**对被操作便签 A 只写实时几何——不写 rec、不刷 UpdatedAt、不落盘**（权威记账仍归松手后的 `NoteMoved/NoteResized`）；`pushPass` 弹开被压者时照常写被弹者几何并防抖落盘（弹开位置是持久事实，语义同 v3.0.0）。
- `pushPass` 尺寸读取小改（self 与 notes 一律实时优先）；其余逻辑零改动。拖动路径的弹开**不打日志**（20Hz 采样连发会刷屏；保留召唤路径日志）。
- 无节流：`ResolveOverlaps` ≤19 张微秒级，50ms 采样足够稀疏；`GlideNote` 同窗口取旧起新天然消化重复触发。
- 锁纪律不变：`pushPass` 锁外调用、锁内只拿几何；采样 goroutine 不持控制器锁调 `win.Position()`（先读窗口再进锁）。

## 5. 接口与数据

- `WindowOps` 接口**零新增**（采样在 main.go wailsOps 层直接读窗口几何，控制器入口只有 `DragLiveTick`）。
- 数据形状无变化（notes.json 仍 v3、settings.json 仍 v2），无迁移；`frontend/bindings` 不受影响（不涉 settingsui 服务）。

## 6. 探针验证（Phase 0，先行任务）

框架行为的唯一不确定点：便签窗口（Frameless + `--wails-draggable: drag`）的**原生拖动/缩放手势是否确实发出 `WindowStartMove/EndMove`、`WindowStartResize/EndResize`**（源码 emit 点已确认存在，但 Frameless + 透明补丁组合下的实际触发未实测）。先行最小探针验证四个事件在拖动与缩放手势下的触发与次序；若 Frameless 拖动不走 `WM_ENTERSIZEMOVE`（可能性低），回退方案 = 改用「`WindowDidMove` 兜底 + 缩短该窗 `WindowDidMoveDebounceMS`」的准实时路径，行为降级为「高频记账点挤开」。探针结论决定 plan 细节。

## 7. 测试

单测（`internal/wm/controller_test.go`，WindowOps 内存替身已有）：

- `DragLiveTick`：更新实时几何并触发挤开（B 被弹开、px/py 写入、placed 写 rec、哨兵保持、UpdatedAt 不刷、不落盘）。
- 缩放 tick：`rw/rh` 参与（放大后矩形压到兄弟 → 挤开）；兄弟实时尺寸优先读取。
- 兜底：`NoteMoved` / `NoteResized` 后残留重叠被挤开。
- 级联 / 装箱兜底 / 屏幕满接受重叠 / 未钉拖压钉住（复用 `ResolveOverlaps` 已测分支的控制器路径验证）。
- 回归：召唤弹开三入口既有用例全绿（`pushPass` 尺寸读取改动不破坏语义）。

手测闸口（新增，全部通过才算交付）：

1. 拖动 A 压 B：B 动画弹开、A 不位移不闪跳；A 持续追压 B 持续让位（推实物手感）。
2. 级联：被弹者撞第三张传导弹开。
3. 拖动中停顿 >50ms：重叠已消解。
4. 快速甩动后松手：松手瞬间残留重叠被兜底弹开。
5. 缩放变大压 C：C 被挤开；缩放参与几何（按实时尺寸）。
6. Win+方向键贴边移动：兜底弹开。
7. 未钉 A 拖压钉住便签：钉住的被挤开。
8. 拖到屏幕满：接受重叠不死循环。
9. 弹后重启：placed 便签恢复弹后位置；哨兵重启重装箱。
10. 召唤弹开三入口回归：行为与 v3.0.0 一致（含缩放过便签参与）。
11. 拖动流畅性：20Hz 采样无卡顿；拖动全程 `data\` 防抖落盘正常。
12. 关窗后采样 goroutine 不泄漏（开/关多张便签后行为正常）。
