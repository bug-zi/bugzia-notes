## 1. 背景与目标

v2.0.0 之前 `toggle` 键曾是「全便签集合切换」，2.0.1 收窄为「只切主便签」。v2.1.0 回归自由便签（`main` 键新建）后，开发者明确两件事：

- 托盘右键的「召唤主便签」不再需要（alt+c 集合切换承接其职责）。
- `toggle` 键（开发者实际配置 alt+c）要**统一管理主便签与自由便签**（alt+shift+c 创建的那些，如果有的话）的召唤出现与收起隐藏——即恢复集合切换语义，但集合范围从「全部便签」收窄为「主便签 + 自由便签」，辅助便签 1~5 仍由各自键独立管理。
- 设置窗口「检查更新」下方新增「查看更新日志」：按项目版本与更新日期展示功能迭代情况。

## 2. 非目标

- 不改辅助便签键（`alt+1`~`alt+5`）与 `ToggleSlot` 的任何行为。
- 不改 `main` 键（新建便签）与 `kill` 键（销毁当前）语义。
- 不改数据形状：notes.json 仍 v3、settings.json 仍 v2，无迁移。
- 更新日志不做 GitHub 拉取、不做自动更新弹窗联动，纯内置静态数据。
- 不改回收站、更新检查、自启动等既有机制。

## 3. 已批准决策（会话确认）

1. **切换规则**：沿用 v2.0.0 已验证的集合规则收窄——展开 = 集合内每张「钉住且可见」；未全展开 → 召唤所有隐藏的 + 未钉住自动升钉（防空转）+ 主便签缺失补建；已全展开 → 全部收起。
2. **召唤聚焦**：聚焦集合内最近活跃（`UpdatedAt` 最大）的一张；补建场景新主便签时间戳必然最大，自然聚焦新主便签。
3. **更新日志数据源**：内置静态数据（前端数据文件随 exe 发布），离线可看；当前版本高亮。每发一版由 AI 在开发时同步补一条。
4. **版本历史**：v2.0.0 之前发布过 v1.0.0（2026-11-17 首版）与 v1.1.0（2026-11-18 回收站 + 检查更新）。

## 4. 集合切换语义（`Controller.ToggleMainSet`）

```
锁内：
  main := Slot==SlotMain 的记录（至多一张）
  set  := (main 若存在) + 全部 Slot==SlotFree 的记录
  expanded := main != nil 且 set 内每张 rec.Pinned 且 c.visible[id]
分支（锁外执行窗口操作）：
  expanded → set 内全部 hideNote(id)
  !expanded →
    a. main == nil → createSlotNote(SlotMain, false)   // 补建：即钉住、装箱、needsFocus
    b. set 内隐藏成员全部 showNote(id)
    c. set 内 rec.Pinned == false 的成员升钉（rec.Pinned=true + ops.SetPinned(id, true)）；
       升钉仅改层级，**不刷新 UpdatedAt**（程序性变更，不污染「最近活跃」语义）
    d. 聚焦目标在升钉前确定：main 刚补建 → 交给 needsFocus 机制（窗口 ready 后聚焦，不同步 FocusNote）
             main 已存在 → 集合内 UpdatedAt 最大的成员 ops.FocusNote(id)，activeID = id
    e. 变更后统一一次 scheduleSave()（升钉 + 补建一并固化）
```

- 集合退化自然成立：无自由便签时 = 单主便签切换（同 2.0.1 现状行为）；主便签缺失且无自由便签（极端）→ 走召唤分支补建主便签。
- 升钉会覆盖用户手动取消的钉住状态——这是「防空转」的既定代价（沉底的未钉便签召唤后必须保证看得见），v2.0.0 已验证接受。
- `ToggleSlot` 原样保留，供辅助键使用；`startRestore` 补建主便签逻辑不变。
- 补建走 `createSlotNote` 的 `canAdd` 上限检查（20）：被拒时 Notify 提示，其余召唤步骤照常进行。

## 8. 设置窗口文案

- 键位区 label：「主便签切换」→「便签集合切换」（input id `hk-toggle` 不变）。
- hint 说明改写：便签集合切换 = 统一管理主便签与自由便签（alt+shift+c 创建的那些）的召唤/收起——未全显示时召唤全部隐藏的（主便签缺失自动补建、未钉住的自动钉住保证可见），全部显示时一次收起；不干涉辅助便签。新建便签、辅助便签、销毁当前的说明不变。

## 9. 错误处理与边界

- 集合为空（主便签缺失且无自由便签）：召唤分支仅补建主便签。
- 补建上限被拒（集合已满 20）：Notify 提示，其余召唤步骤照常。
- 聚焦目标窗口必已存在（未补建场景集合成员均已建窗；补建场景走 needsFocus），无「聚焦未 ready 窗口」路径。
- 升钉无变化的成员不触发 `ops.SetPinned`；变更后一次防抖落盘。
- 收起分支对处于销毁确认态的便签无特殊处理（与现有 `ToggleSlot` 收起行为一致）。

## 10. 测试策略

单测（go test，WindowOps 内存替身）：

- 召唤：主（隐藏）+ 自由 A（隐藏）+ 自由 B（可见未钉）→ 切换后全部可见、B 升钉、聚焦 `UpdatedAt` 最大者、activeID 同步。
- 收起：集合内全部钉住且可见 → 切换后全部隐藏；同屏辅助便签可见性与钉状态不变。
- 补建：无 Slot=0 记录 → 切换后补建主便签（Slot=0、pinned、装箱、needsFocus 挂起），隐藏自由便签同召。
- 辅助隔离：辅助便签显示中反复切换集合，其可见性/钉状态/activeID 不被扰动。
- `TestLabelCoversEightKeys` 期望更新为「便签集合切换」。

手测闸口（全部通过才算交付）：

1. alt+c 往返：全收 → 全显 → 全收；手动取消某自由便签钉住后按 alt+c，该便签被召唤且恢复钉住。
2. alt+z 销毁主便签后按 alt+c：主便签补建并聚焦。
3. 辅助便签显示中反复 alt+c：辅助便签始终不受扰。
4. 托盘菜单为「回收站 / 设置 / 退出」，无「召唤主便签」。
5. 设置窗口：更新日志展开/收起、当前版本高亮、内容可滚动、配色与主题同源。
