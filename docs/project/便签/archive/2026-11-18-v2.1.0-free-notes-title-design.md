# bugzia-notes 设计 — v2.1.0 自由便签回归 + 辅助便签样式设置 + 便签标题

> 创建于 2026-11-18（会话需求确认）。本文档由 AI 依开发者需求起草，维护权责见 `docs/project/README.md`。
> 前置：`2026-11-18-slot-model-design.md`（6 槽位模型，已落地 v2.0.0）。
> 已归档：261118 随 v2.1.0 落地（手测闸口开发者确认通过）。

## 1. 背景与目标

v2.0.0 槽位模型把便签收敛为 1 主 + 5 辅固定槽位，删掉了 v1 的自由创建语义（原 alt+shift+c 一直新建）。实践后开发者明确：

- 5 个辅助便签定位为「额外拓展」，**原 alt+shift+c 的「可创建多便签」要回来**：连按连建，新便签用默认样式——这样「便签独立样式设置」与「全局默认样式」才有意义。
- 辅助便签也应有「设置」（样式面板），可锁定独立样式，不必被槽位色焊死。
- 每张便签顶部（「设置」按钮左侧）显示标题，默认「便签n」，双击可改名。

## 2. 非目标

- 不改 6 槽位语义本身：`ToggleSlot` 三态、槽位唯一性、启动补建主便签、托盘菜单均不动。
- 不改 `toggle` 键（alt+n）与 `kill` 键（alt+z）语义。
- 不做标题在回收站窗口的展示（回收站条目仍只有内容）。
- 不加「重命名」的其他入口（仅双击标题）。
- 不改窗口 Win32 Title（= id，句柄查找依赖），标题纯前端展示。

## 3. 已批准决策（会话确认）

1. **新建键语义**：`main` 键（默认 alt+c，开发者实际配置 alt+shift+c）改回「新建便签」；存在隐藏自由便签时**先召唤最近更新的一张**（覆盖静默启动恢复的隐藏便签），全部可见时再新建。
2. **总量上限 20**：槽位便签 + 自由便签共享，超限通知提示。
3. **默认标题编号**：n 从「创建后的便签总数」起试，重名自动 +1 顺延，永不重名（常规场景 n 即当前便签数量）。

## 4. 领域模型

```
model 常量变更：
  MaxNotes  6 → 20          // 回归 v1 语义：便签总数上限（含槽位）
  SlotCount = 6（新增）      // 槽位数：ToggleSlot 越界判定（0..SlotCount-1）、辅助槽位范围
  SlotFree  = -1（新增）     // 自由便签槽位哨兵：与槽位便签同列表同存储，仅 Slot 值不同

NoteRecord 新增字段：
  Title string `json:"title"`   // 便签标题；空值由加载迁移补默认（§5）
```

- 自由便签 = `Slot == SlotFree` 的记录。`ToggleSlot` 的越界检查（`slot < 0`）天然忽略自由便签，槽位查找 `rec.Slot == slot` 不会误命中。
- `canAdd` 改为 `len(notes) < MaxNotes(20)`，槽位创建与自由创建共用。
- `NewRecord` 签名不变；标题由控制器在创建时赋（需要现有标题集合，模型层不感知）。
- 默认标题纯函数放 model 层（可单测）：`NextDefaultTitle(taken map[string]bool, start int) string` —— 从 `start` 起试「便签n」，被占用则 n+1，返回首个未占用的（含「便签」前缀）。调用方 start 取「创建后的便签总数」（现有数 + 1）。

## 5. 数据与存储升级

### 5.1 notes.json v2 → v3

- `writeNotes` 版本号 2 → 3。
- `LoadNotes`：`Version >= 3` 直接返回；`Version == 2` 就地补标题后**立即以 v3 重写**（atomic 原子写，**不做备份改名**——迁移纯增量非破坏，v2 文件本身可回读，无 v1→v2 那种「改名后重写失败=丢文件」窗口）；`Version < 2` 仍先走原 v1→v2 迁移（备份改名、取最新为主便签），产物再补标题成 v3。
- **标题补默认（幂等，对所有版本统一执行）**：按文件顺序遍历，`Title` 为空的记录依次取 `NextDefaultTitle`（taken 集合含已有非空标题与本次已分配的）；v3 文件里空标题同样在内存补齐，待下次防抖落盘自然固化。

### 5.2 settings.json 不升级

- 仍为 v2。`hotkeys.main` 字段名不变，仅语义变化（§6），无形状迁移。

### 5.3 默认值

- 无新增设置项。`HotkeySettings.Main` 注释更新为「新建自由便签」。

## 6. 快捷键体系

- `IDMain` 语义：主便签切换 → **新建便签**。`dispatchHotkey` 改为：
  - `IDToggle` → `ToggleSlot(SlotMain)`（不变）
  - `IDMain` → `CreateOrSummonFree()`（新）
- `hotkey.Label(IDMain)`：主便签 → 「新建便签」（冲突报告、日志用）。
- 其余键不变。`ParseAll` 不变（字段名没变）。

## 7. 交互语义

### 7.1 CreateOrSummonFree（main 键新入口）

```
锁内：收集 Slot==SlotFree 的便签及其可见性
  存在隐藏者 → 取 UpdatedAt 最大的一张（最近更新优先）
锁外：showNote(id) + FocusNote(id)，activeID = id（召唤即当前便签）
无隐藏者（含完全没有自由便签）→ createFreeNote()
```

- `createFreeNote`：上限检查（20，超限通知「便笺已达上限（20）」）→ `NewRecord("", 全局W/H, pinned=true)` → `Slot = SlotFree` → 赋默认标题 → 装箱定位显示聚焦（同 `createSlotNote` 路径：`needsFocus` 注水后聚焦、`activeID` 即为它）。
- 连按连建：全部可见时每次按都新建一张；静默启动后第一次按先唤回隐藏的自由便签。
- 自由便签的显隐：无专属切换键；静默启动恢复的靠召唤键唤回，其余生命周期内常显（销毁走 kill 键确认链）。

### 7.2 槽位便签创建补标题

- `createSlotNote`（主/辅）同样赋默认标题；上限提示文案 6 → 20。`startRestore` 补建主便签走同一路径自动带标题。

### 7.3 标题编辑（前端）

- 头部布局：`[拖动条] [标题……] [设置][钉住][复制][销毁]`，标题在设置左侧，`flex:1` 弹性占位、超长省略号截断；标题区域保持 `--wails-draggable: drag`（可从标题拖动窗口）。
- **双击标题** → 行内切 `<input>`（no-drag，maxlength=30）：Enter/失焦提交，Esc 取消还原；提交值 trim 后为空则保持原标题不提交。
- 提交走新事件 `note:renamed {id, title}` → 控制器 `SetTitle(id, title)`：trim + 按 rune 数截断到 30 → 写 `rec.Title`（仅变化时刷 `UpdatedAt`）→ 防抖落盘 → **单窗重推 hydrate**（前端以规范化后的标题回显）。
- 标题编辑态期间收到 hydrate：跳过标题回显（避免打断输入），编辑结束后由提交路径的重推自然对齐。

### 7.4 销毁链

- 自由便签销毁与槽位便签同一条链（`ConfirmDestroy` 尾部挂钩入回收站），无额外处理。

## 8. 样式组合（辅助便签开放设置）

- 删除 `SetNoteStyleLock` / `ApplyNoteStyleFor` 中 `Slot >= 1` 的拒绝分支——**所有便签**（主/辅/自由）均可锁定独立样式。
- `EffectiveStyle` 逻辑不变，优先级仍旧 **样式锁 > 槽位色 > 全局**：
  - 锁定（任意便签）→ 完全用锁定快照；
  - 辅助未锁定 → 底色 = 槽位色，圆角/字号/透明度跟随全局；
  - 主/自由未锁定 → 完全跟随全局（自由便签默认样式，即「独立设置有意义」的基线）。
- 前端 `note.js`：
  - `btn-style` 对辅助便签不再隐藏（删除 `btnStyle.hidden = slot >= 1` 及面板联动关闭）。
  - 锁定按钮文案：锁定 → 「已锁定（独立样式）」；未锁 → 辅助「跟随槽位色」、其余「跟随全局」。提示行文案同步（「当前跟随槽位色，锁定后可单独修改」/「当前跟随全局默认，锁定后可单独修改」）。
  - 「已钉住」字色（`--note-pin-ink`）规则推广：**辅助或已锁定便签 = 生效底色**（锁定后即快照色），其余回落深红 `#9e1b32`（2.0.1 行为保持）。

## 9. 设置窗口 UI

- 键位区：「主便签」标签 → 「新建便签」（input id `hk-main` 不变）。仅改 `index.html` 文案；`settings.js` 按 id 读写，不动。
- 键位说明改写：主便签切换 = 只切主便签显隐（首次按下自动创建）；新建便签 = 新建一张自由便签（默认样式，可在便签上锁定独立样式），若存在隐藏的自由便签则先召唤最近一张；辅助便签 1~5 = 固定五槽位逐个召唤。
- 辅助颜色区提示补：未锁定时底色 = 槽位色（实时生效），便签内锁定样式后独立。

## 10. 错误处理与边界

- 上限 20 对六槽位键与新建键统一生效；`Notify` 仍是日志（v1 简化，不变）。
- 标题：Go 侧按 rune 截 30 上限（前端 maxlength 只是第一道）；空/纯空白标题不覆盖旧值。
- `SetTitle` 的便签 id 不存在时静默返回（与 `SetContent` 同款防御）。
- v2→v3 重写失败仅记日志（内存态已生效，防抖补写）；迁移幂等，下次启动重试。
- hydrate 载荷新增 `title` 字段，前端渲染即 Go 所发值（迁移与创建路径保证非空；异常为空时标题区留空，不阻塞便签功能）。

## 11. 测试策略

单测（go test）：

- `CreateOrSummonFree` 三态：无自由便签 → 新建（SlotFree、即钉住、装箱、activeID）；有隐藏 → 召唤 UpdatedAt 最近一张且不新建；全部可见 → 再新建。
- 总量上限：19 张时新建成功、20 张时新建被拒且槽位键同样被拒。
- `NextDefaultTitle`：空集合从 1 起；连续分配不重名；「便签3」被占用时顺延；自定义标题不参与编号但参与占用判定。
- `SetTitle`：trim、30 rune 截断、空白不覆盖、id 不存在静默、UpdatedAt 语义。
- `EffectiveStyle`：辅助锁定覆盖槽位色；辅助解锁回槽位色；自由便签跟随全局。
- 样式锁：辅助便签 `SetNoteStyleLock` 成功（不再拒绝）。
- 存储：v2 → v3 补标题 + 立即重写 v3（幂等，二次加载不再触发）；v1 直迁 v3（备份 + 主便签 + 标题）；v3 空标题内存补齐。

手测闸口（全部通过才算交付）：

1. 连按新建键（alt+shift+c）连建多张，均为默认玫红样式、装箱错开、自动聚焦。
2. 静默启动（`--silent`）后按新建键：第一次先唤回隐藏自由便签，之后连按新建。
3. 辅助便签「设置」按钮出现；锁定后改色生效且改全局默认不影响它；解锁回到槽位色；「已钉住」字色锁定后随快照色、解锁后随槽位色。
4. 双击标题改名的全链路：Enter/失焦提交、Esc 还原、超 30 字截断、空白不生效、重启后保留、超长省略号显示。
5. 槽位便签（主/辅）同样有标题且默认编号顺延；销毁自由便签入回收站；总数到 20 后槽位键与新建键都有上限提示。
6. `go build ./...` + `go vet ./...` + `go test ./...` 全绿。
