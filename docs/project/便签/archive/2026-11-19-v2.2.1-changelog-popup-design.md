# bugzia-notes 设计 — v2.2.1 更新日志改为独立弹窗

> 创建于 2026-11-19（会话需求确认；v2.2.0 验收通过后的小迭代）。维护权责见 `docs/project/README.md`。
> 已归档：261119 随 v2.2.1 落地（手测闸口开发者确认通过）。
> 前置：`2026-11-19-v2.2.0-collection-toggle-changelog-design.md`（已验收）。

## 1. 背景与目标

v2.2.0 的更新日志为设置窗口内嵌展开区，实践后开发者要求改为**弹窗形式**：点击「查看更新日志」弹出独立小窗（形态已确认：独立单例窗口，与回收站窗口同模式）。

## 2. 决策（会话确认）

- 弹窗 = **独立单例窗口**（Name="changelog"，Title「bugzia-notes 更新日志」，460x600，对齐 openTrash 模式；已存在则显示并聚焦）。
- 设置窗口按钮点击 → 服务方法 `OpenChangelog`（回调注入，同 `SetUpdateCheck` 模式）→ main 的 `openChangelog(app)`。
- 渲染逻辑与静态数据合并进 `frontend/assets/changelog.js`（数据 + 视图，单一消费方 changelog.html）；settings.js 不再渲染。
- 版本号 v2.2.1，更新日志数据补 v2.2.1 条目。

## 3. 变更清单

- `internal/settingsui/service.go`：`Service.openChangelog func()` 字段 + `SetOpenChangelog` 注入 + `OpenChangelog()` 方法（nil 时静默返回）；`Version` → v2.2.1。
- `main.go`：`svc.SetOpenChangelog(func() { openChangelog(app) })`；新增 `openChangelog`（单例窗口）。
- `frontend/changelog.html`（新）：panel + h2「更新日志（新到旧）」+ `#list.changelog` 容器。
- `frontend/assets/changelog.css`（新）：深色底基础样式 + 列表样式（自 settings.css 迁入，玫红同源）。
- `frontend/assets/changelog.js`：数据外新增 `renderChangelog(box, currentVersion)`。
- `frontend/index.html`：删除内嵌 `<div id="changelog">`（按钮保留）。
- `frontend/assets/settings.js`：删除渲染块 / `currentVersion` / `CHANGELOG` import；按钮改为调用 `OpenChangelog`。
- `frontend/assets/settings.css`：删除 `.changelog*` 规则（迁至 changelog.css）。
- 绑定：新增服务方法，**需重新生成** `wails3 generate bindings`。

## 4. 边界

- `OpenChangelog` 在回调未注入（理论上不可能）时静默返回，不报错。
- 弹窗为纯查看，无编辑面；数据为内置静态，无网络依赖。
- 无新增单测面（窗口接线与回调转发）；验证 = 全量回归 + 手测。

## 5. 手测闸口

1. 设置窗口点「查看更新日志」：弹出独立小窗，列表新到旧、v2.2.1 行标「当前版本」、内容可滚动、配色与主题同源。
2. 重复点击：单例（不叠开），已打开则置前聚焦。
3. 关闭弹窗后再点：正常重开。
4. 设置窗口不再出现内嵌展开区；其余设置功能不受影响。
5. `go build ./...` + `go vet ./...` + `go test ./...` 全绿。
